# Person-first programming integration — 2026-11-19

Historical initial-integration record for source checkpoint 03f76f6. The owner's subsequent expanded request is implemented in [BUILD121_PROGRAMMING.md](BUILD121_PROGRAMMING.md); that document supersedes the initial "remaining" entries where it describes completed macro/preset, exercise-adjustment, quality-running and practice-block work.

This change connects Drew’s supplied training framework to the current StrideOS generator. It adds a bounded new-goal programming version, improves performance advice, and preserves existing goal plans rather than silently replacing their exercise prescriptions.

## Scope and preservation boundary

- No images, share images, artwork, native Watch code, authentication, billing, or cloud services changed for this work.
- Existing persisted goal plans use strength programming version 1. Missing or malformed version data hydrates as version 1. Changing a start date or lifting preferences alone does not upgrade an existing goal.
- Explicitly choosing a new goal opts into version 2. Existing saved beginner plans retain their stored plan structure.
- An already-started generated strength workout displays its captured title, exercise list, order, sets, reps and launch context even when a new week no longer contains it. It does not replace those from a subsequently recomputed generator list. New launches capture week/type/goal and warmup/cooldown context. Legacy active drafts without that metadata finish as manual records with explicitly labeled neutral compatibility metadata, never a guessed current goal/week.
- Live completion uses the retained workout instance as its unique identity. It checks history hydration and ownership, confirms local strength history and the Activity projection by readback, and only then clears the same active draft. A failed save retains the draft for an idempotent retry. Positive load picker values persist explicit units, so restoring after a unit switch preserves the original measured load.
- New completions retain an optional original prescription snapshot separately from actual set execution. Historical records lacking a prescription snapshot remain unknown; this change does not reconstruct or overwrite them. Calendar summaries still derive from plan projections, so this is not a claim that all historical displayed prescriptions were already captured.
- Completed activity and actual strength records are not edited by generation. Rest-day placement is a stable prospective rule for new version-2 generated weeks; completion flags do not change the paired lift date. If an incompatible already-completed or active session prevents an omission, the generator retains it and requests review.
