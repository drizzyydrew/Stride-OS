Engineering preparation for the normal billing-off candidate; not legal advice,
live privacy-label publication or public-review acceptance.

## Changes and existing disclosures

The new name/username fields fit the existing Name disclosure. Local visibility
choices affect profile/greeting/new Coach context, not whether previously sent
information can be recalled. The optional AI context still follows the existing
owner-bound Anthropic consent flow; no public directory or globally unique
username service was added. Do not market these choices as anonymous accounts.

Explicit race/time-trial results, personal bests and their calibration/achievement
derivatives fit the existing Fitness/Health and account-bound training scope.
The per-owner PR celebration ledger is local app state; no new advertising or
public sharing destination is introduced. Share Studio preview is distinct from
the owner's eventual explicit share action.

The Watch permission request was consolidated under Health setup. Existing
optional read-data scopes and workout writing still need clear native choices;
removing the separate setup button does not grant permissions. Hiding raw sync
panels does not change the existing optional usage/diagnostic collection policy.

For this billing-off candidate, retain/reconcile the previously published
11-type matrix in `PRIVACY_LABEL_RECONCILIATION.md`. The supported metadata pull
does not retrieve Apple's live privacy-label answers, so this review does not
claim a fresh 11-type readback. Before a paid launch use the separate Purchase
History/User ID overlay and actual integration/lifecycle outcomes.

Activity history and Strength presets, three older iPad captures and four older
Watch captures. File names/counts are not final-candidate acceptance. Original
files and library assets must be preserved when replacing their placements.

Apple's current [screenshot specifications](https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications/)
list required iPhone display coverage and supported scaling fallbacks, conditional
iPad coverage and Watch sizes. Check the actual required Media Manager wells
against the final binary; do not rely on the older “6.5/6.9 only” shorthand.
This host remains iPhone-only. Apple's [Watch metadata guidance](https://developer.apple.com/help/app-store-connect/create-an-app-record/add-watchos-app-information/)
calls for actual Watch screenshots and functionality description. Old readiness
and stats artwork is not accepted merely because it is already uploaded.

Keep source/build provenance for every genuine capture. Do not redraw app UI,
resize unrelated phone imagery into a different device or publish personal
routes, health data, credentials or another user's identity to fill a slot.
The existing six-phone/three-Watch storyboard remains a capture plan; the minimum
required coverage is whatever Apple's current wells require for the candidate.
